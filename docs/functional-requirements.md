# Fitlix — функциональные требования

**Версия:** 1.0  
**Статус:** черновик для согласования  
**Назначение продукта:** облачный дневник силовых и кардиотренировок.

## 1. Цель продукта

Fitlix помогает пользователю вести историю тренировок по датам: выбирать упражнения из каталога, записывать подходы, вес и повторы, просматривать занятия в календаре и повторно добавлять упражнения из прошлых тренировок. Данные пользователя хранятся в облаке и доступны после входа в аккаунт.

## 2. Пользователи и границы первой версии

Основной пользователь — человек, который самостоятельно записывает свои тренировки. В первой версии не предусматриваются тренерские аккаунты, совместное ведение дневника, планы тренировок, социальная лента, аналитика прогресса и интеграция с фитнес-устройствами.

## 3. Функциональные требования

Приоритеты: **M — обязательно для первой версии**, **S — желательно**.

### 3.1. Аккаунт и облачные данные

- **FR-01 (M).** Система должна позволять пользователю создать аккаунт и войти в него.
- **FR-02 (M).** Система должна сохранять тренировки и пользовательские упражнения в аккаунте пользователя.
- **FR-03 (M).** После входа пользователь должен видеть свои данные с разных устройств; изменения должны синхронизироваться с облаком.
- **FR-04 (M).** Данные одного пользователя не должны быть доступны другим пользователям.

### 3.2. Каталог упражнений

- **FR-05 (M).** Система должна предоставлять каталог упражнений двух типов: силовые и кардио.
- **FR-06 (M).** У каждого упражнения должны быть название, тип и категория.
- **FR-07 (M).** Для силовых упражнений система должна поддерживать категории по группам мышц. Начальный набор категорий: ноги, спина, грудь, плечи, руки, корпус.
- **FR-08 (M).** Для кардио должна быть доступна категория «Кардио».
- **FR-09 (M).** Пользователь должен иметь возможность найти упражнение в каталоге и отфильтровать список по типу и категории.
- **FR-10 (S).** Пользователь должен иметь возможность добавлять собственные упражнения, указывая название, тип и категорию. Пользовательские упражнения видны только создавшему их пользователю.

### 3.3. Дневник тренировок

- **FR-11 (M).** Пользователь должен иметь возможность открыть дневник за выбранную дату и добавить к этой дате упражнения из каталога.
- **FR-12 (M).** В одной тренировке можно записать несколько упражнений; порядок упражнений должен сохраняться.
- **FR-13 (M).** Для каждого упражнения в тренировке пользователь должен иметь возможность указать количество подходов.
- **FR-14 (M).** В каждом силовом подходе пользователь должен иметь возможность записать вес и количество повторений.
- **FR-15 (M).** Пользователь должен иметь возможность изменить или удалить упражнение в тренировке, а также изменить или удалить отдельный подход.
- **FR-16 (M).** Система должна показывать общее количество упражнений за выбранный день и количество подходов у каждого упражнения.
- **FR-17 (M).** Пользователь должен иметь возможность удалить тренировку за выбранную дату. Удаление должно требовать подтверждения.
- **FR-18 (S).** Для кардио-упражнения пользователь может указать длительность и дистанцию. Эти показатели не обязательны для сохранения записи.

### 3.4. Повторное добавление упражнений

- **FR-19 (M).** Пользователь должен иметь возможность выбрать другую дату с сохранённой тренировкой и добавить упражнения из неё в текущую дату.
- **FR-20 (M).** Система должна позволять выбрать отдельные упражнения для переноса или добавить все упражнения тренировки.
- **FR-21 (M).** При переносе копируются упражнение и его подходы с записанными значениями веса и повторений. Новая запись относится только к текущей дате; изменение или удаление копии не должно менять исходную тренировку.
- **FR-22 (M).** До добавления система должна показать, какие упражнения будут скопированы, и дать пользователю подтвердить действие.

### 3.5. Календарь

- **FR-23 (M).** Система должна показывать календарь по месяцам и позволять переходить к предыдущему и следующему месяцу.
- **FR-24 (M).** В календаре должны быть визуально отмечены даты, на которые записаны тренировки.
- **FR-25 (M).** Выбор даты в календаре должен открывать дневник за эту дату.
- **FR-26 (M).** Пользователь должен иметь возможность создать тренировку, выбрав дату без тренировки.
- **FR-27 (M).** При переходе между датами или месяцами уже сохранённые записи должны отображаться для соответствующих дат.

## 4. Основные правила данных

- Каждая тренировка принадлежит одному пользователю и одной календарной дате.
- Упражнение в каталоге имеет один тип: силовое или кардио.
- Запись упражнения в тренировке хранит ссылку на упражнение и собственный список подходов.
- Силовой подход хранит порядковый номер, вес и число повторений. Вес может быть дробным числом; единица измерения веса по умолчанию — килограммы.
- Количество упражнений за день рассчитывается по числу записей упражнений в тренировке, а не вводится вручную.
- Количество подходов рассчитывается по числу подходов, добавленных для упражнения.
- Повторное добавление создаёт независимую копию записи и подходов.
- Пустая дата в календаре не считается тренировкой, пока пользователь не добавил хотя бы одно упражнение.

## 5. Критерии приемки первой версии

1. Пользователь может создать аккаунт, войти и увидеть собственный дневник.
2. В каталоге доступны силовые и кардио-упражнения; силовые упражнения можно найти по группе мышц.
3. Пользователь может создать тренировку на выбранную дату, добавить упражнения, указать подходы, вес и повторы, а затем изменить или удалить записи.
4. Количество упражнений за день и подходов для каждого упражнения отображается и соответствует сохранённым записям.
5. Пользователь может открыть прошлую тренировку, выбрать часть или все упражнения и добавить их в другую дату; скопированные записи можно редактировать независимо.
6. Календарь показывает даты тренировок, позволяет переключать месяцы и открывать дневник выбранного дня.
7. После повторного входа и на другом устройстве пользователь видит синхронизированные данные своего аккаунта.

## 6. Допущения и вопросы к уточнению

- Поля кардио (длительность и дистанция) включены как предложение для минимально полезной записи кардио; их можно исключить, если в первой версии достаточно только названия упражнения и факта выполнения.
- В первой версии предполагаются килограммы и календарная дата без времени начала тренировки.
- Не определены способы входа (например, электронная почта и пароль или сторонний провайдер), восстановление доступа и политика хранения удалённых данных — это нужно уточнить перед проектированием реализации.
- Категории в документе — начальный набор; нужно подтвердить, какие группы мышц и пользовательские категории требуются.
